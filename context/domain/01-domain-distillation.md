# Domain distillation: Critical Path

A map of the business domain, built from the product documents and from the code as found on branch `domain-distillation` at `4c7b2b9`. It describes, and does not change, production code. Every term carries its source. Line numbers were checked against the files at the time of writing.

> **Point-in-time snapshot, not updated as slices land.** Terms, rules and drift items describe the code at `4c7b2b9`; later slices changed some of them (S-07 removed the import rejection UL-37 names and made DR-03's "No edit sets a Status" untrue). For the current terms and Validation Errors, read `context/domain/glossary.md` and `context/foundation/prd.md`.

## Step 0: Project context

**Source documents read.** `context/foundation/prd.md` (v1, the product spec), `context/foundation/shape-notes.md` (the discovery record, including the verbatim seed idea at line 89 and the resolved gray areas at lines 9–71), `context/foundation/roadmap.md` (milestone M-1, slices F-01 and S-01–S-08), `context/foundation/tech-stack.md`, `context/foundation/test-plan.md`, `context/foundation/lessons.md`, `README.md`, `PROJECT_RULES.md`, and the archived plan `context/archive/2026-10-13-render-crash-recovery/plan-brief.md` for a later decision. Requirements documents exist, so this map isn't limited to the README.

**Stack.** Astro 7 with static output and a single React 19 island, TypeScript and Tailwind 4 (`README.md:7-10`, `tech-stack.md:30`). The app has no server, API, database or auth, by design (`astro.config.mjs` sets `output: "static"`). The CSP's `connect-src 'none'` enforces "no project data leaves the device".

**Layers and where the business logic lives.**

**Why #1 is RK-01.** The Guardrail "A project never contains a Validation Error" is the PRD's strictest rule (`prd.md:66`) and sits in the Core. The code enforces it today, but through rule-by-rule checks scattered across edits, plus a second checker for import. That has worked while the rules were local: a name, a Duration, one new edge. The next slice (S-07) brings rules that are _indirect_ by definition. Reverting one Task's Status can break its successor, and moving the START date can break any completion date. Local checks in each edit can't see those, and `forecast()` already assumes they hold (`src/lib/services/forecast.ts:76-80`). Making the Project the single guardian of the resulting state before S-07 means the Done rules are written once and checked everywhere. It also turns the cycle duplication (DR-07) and the import bypass (RK-06) into consequences of one design rather than separate fixes.

## Summary

This map names 37 domain concepts, each with its source in the PRD or shape notes and its place in the code. Four concepts the PRD requires have no counterpart in the code: the critical path, critical-path and total-work time, maximum parallelism as a parameter, and unexported changes. It records eight words that change meaning between contexts, most sharply "Task" (START and FINISH were "special Tasks" in the seed idea and are never Tasks in the code), "dependency" (stored vs drawn) and "Validation Error" (a state in the PRD, a rejection value and an import result in the code). The subdomains split into a Core of graph rules, forecast, critical path and progress; a Supporting ring of the project file, diagram, day-counting mode, safe replacement and the local-only guarantee; and Generic date arithmetic, graph algorithms and libraries. Of 23 invariants, most are enforced and tested. The weak ones cluster around progress: the Done rules exist only as a temporary import block, and the forecast already depends on them. The drift list has 14 entries; two are settled by later decisions (the crash-screen export, the START → FINISH path check), five are code gaps (four of them already planned in the roadmap; the id ceiling is not), and seven need an owner decision. The most important conclusion: before roadmap S-07, make the Project the single guardian of "never a Validation Error". The Done rules are indirect by nature, and the current rule-per-edit checks plus a separate import checker would have to repeat them in at least five places.
