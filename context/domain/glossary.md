# Glossary: Critical Path

Use these terms in code, plans, UI copy and conversation. Evidence and sources are in `context/domain/01-domain-distillation.md`.

| Term                                       | What it means                                                                                                                                                                                                                                             | Name in the code                                                                                                                                                                                                             | Don't call it                                                |
| ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| Project                                    | The one thing the user edits, exports and imports: name, START, FINISH, day-counting mode, Tasks.                                                                                                                                                         | `Project`                                                                                                                                                                                                                    | plan, document, board                                        |
| Task                                       | A unit of work: name, predecessors, optional Duration, Status, completion date. START and FINISH are never Tasks.                                                                                                                                         | `Task`                                                                                                                                                                                                                       | issue, ticket, item, node (in domain code), "the START Task" |
| Task id                                    | A constant, auto-generated identity, never reused. Names need not be unique.                                                                                                                                                                              | `TaskId`, `Task.id`, `nextTaskId`                                                                                                                                                                                            | key, index, position                                         |
| Task name                                  | Text identifying a Task to a human: trimmed, 1–200 UTF-16 code units, visible, no control characters.                                                                                                                                                     | `Task.name`, `checkName`, `taskLabel` ("7: Name")                                                                                                                                                                            | title, label (except `taskLabel`)                            |
| Project name                               | The project's name, which is also the exported file's name. Empty input clears it.                                                                                                                                                                        | `Project.name`, `setProjectName`                                                                                                                                                                                             | title, file name                                             |
| START                                      | The node every project begins from. It has no predecessors and holds the START date.                                                                                                                                                                      | `Start`, `START_NODE_ID`, `"start"` (selection)                                                                                                                                                                              | Start Task, root, source                                     |
| START date                                 | The project start date, set on START. When unset, today is used.                                                                                                                                                                                          | `Start.date`, `setStartDate`                                                                                                                                                                                                 | project start, kick-off date, Task start date                |
| FINISH                                     | The node every project ends in. Nothing depends on it.                                                                                                                                                                                                    | `Finish`, `FINISH_NODE_ID`                                                                                                                                                                                                   | End, Finish Task, sink                                       |
| Predecessor                                | A Task that must be Done before another can start. The only stored direction.                                                                                                                                                                             | `Task.predecessors`, `addPredecessor`, `removePredecessor`                                                                                                                                                                   | parent, blocker, prerequisite                                |
| Successor                                  | A Task that has a given Task as a predecessor. Derived, never stored.                                                                                                                                                                                     | `successorsOf`                                                                                                                                                                                                               | child, dependent (as an identifier)                          |
| Dependency (A → B)                         | "B depends on A". In prose it also covers the implied links to START and FINISH.                                                                                                                                                                          | No identifier; `predecessors` in the model, the edge kind `dependency` in the diagram                                                                                                                                        | link, relation, "is blocked by"                              |
| Hangs off START / feeds FINISH             | The derived links of a Task without predecessors or without successors. Never stored.                                                                                                                                                                     | The edge kinds `hangs-off-start` and `feeds-finish` in `projectDiagram`                                                                                                                                                      | default dependency, START predecessor                        |
| Cycle                                      | A dependency chain that returns to its start. A Validation Error, rejected at input and named.                                                                                                                                                            | `"cycle"`, `cyclePathFor`, `findCycle`                                                                                                                                                                                       | loop, circular reference                                     |
| Duration                                   | A Task's length as a positive whole number of days (or weekdays). Empty is allowed.                                                                                                                                                                       | `Task.duration`, `setDuration`, `formatDuration` (`duration.ts`)                                                                                                                                                             | estimate, effort, length, size                               |
| Status                                     | To Do, In Progress or Done. Only Done counts for the forecast. A Task can be In Progress only when all its predecessors are Done; an In Progress Task with a predecessor that is not Done is a Validation Error.                                          | `TaskStatus` (`"to-do"`, `"in-progress"`, `"done"`), `"in-progress-predecessor-not-done"`                                                                                                                                    | state, progress, "complete", "finished"                      |
| Done                                       | The only Status that counts as finished. It requires a completion date and all predecessors Done; a Done Task missing either is a Validation Error.                                                                                                       | `"done"`, `setStatus`, `"done-without-completion-date"`, `"done-predecessor-not-done"`                                                                                                                                       | complete, finished, closed                                   |
| Completion date                            | The date a Done Task was done. Reserved for that meaning alone. Only a Done Task has one, and it is a calendar date, today or earlier, not before the START date (when one is set) and not before any predecessor's; anything else is a Validation Error. | `Task.completionDate`, `setCompletionDate`, `"completion-date-without-done"`, `"completion-date-not-a-date"`, `"completion-date-after-today"`, `"completion-date-before-start-date"`, `"completion-date-before-predecessor"` | finish date, done date, finalization date, end date          |
| Day-counting mode                          | Calendar days or weekdays (Mon–Fri). A per-project setting saved in the file.                                                                                                                                                                             | `DayCountingMode` (`"calendar-days"`, `"weekdays"`)                                                                                                                                                                          | calendar, working days, business days                        |
| Validation Error                           | A state the project may never hold. The edit is rejected at input and the message names the rule.                                                                                                                                                         | `ValidationError`, `ValidationErrorRule`, `validateProject`                                                                                                                                                                  | invalid, conflict, blocked, error (alone)                    |
| Validation Warning                         | A state the project may hold, export and import. It withholds both Project Finish Dates. Today, only: a not-Done Task without a Duration.                                                                                                                 | `ValidationWarning`, `validationWarnings`, `"duration-missing"`                                                                                                                                                              | warning (alone), soft error, issue                           |
| Checked project                            | A Project the guardian found free of Validation Errors. The only kind the session (initial project, Replacement, Previous project), import and the forecast take. Minted only in `project.ts`.                                                            | `CheckedProject`, `checkProject` (import's door), `toCheckedProject` (hand-built fixtures)                                                                                                                                   | valid project, invalid project, validated project            |
| Guardian                                   | The Project aggregate's own check of the whole resulting Project, never just the edit. Every edit and every import passes through it; it accepts or returns the first Validation Error.                                                                   | `accept` (edits), `checkProject` (import)                                                                                                                                                                                    | validator, validation layer                                  |
| Rule list                                  | The aggregate's one list of Validation Error rules: per-Task checks, run Task by Task, then whole-Project checks. A new rule is one entry.                                                                                                                | `TASK_CHECKS`, `PROJECT_CHECKS`, `validateProject`                                                                                                                                                                           | validators, validation rules (as separate checks)            |
| Task id limit                              | The highest Task id a project can hold (`nextTaskId` at most 2147483647). At it, creating a Task is the Validation Error `task-id-limit-reached`.                                                                                                         | `MAX_TASK_ID`, `MAX_NEXT_TASK_ID`, `"task-id-limit-reached"`                                                                                                                                                                 | id overflow, invalid id                                      |
| Project invariant breach                   | A broken model shape (Task ids or predecessors not strictly ascending, `nextTaskId` not above every id), or a Validation Error where the aggregate promised none. A code bug, never a user mistake.                                                       | `ProjectInvariantBreach`, `assertModelShape`                                                                                                                                                                                 | Validation Error (it isn't one), user error                  |
| Resource-Unconstrained Project Finish Date | The end of the longest path through remaining work, with unlimited parallelism.                                                                                                                                                                           | `resourceUnconstrainedProjectFinishDate`                                                                                                                                                                                     | ETA, deadline, earliest date, finish date (alone)            |
| Resource-Constrained Project Finish Date   | The base date plus the sum of not-Done Durations, with maximum parallelism 1.                                                                                                                                                                             | `resourceConstrainedProjectFinishDate`                                                                                                                                                                                       | ETA, deadline, latest date, worst case, finish date (alone)  |
| Project Finish Dates                       | Both of the above together.                                                                                                                                                                                                                               | `Forecast` (`kind: "forecast"`)                                                                                                                                                                                              | finish dates, end dates, ETAs                                |
| Forecast                                   | Both Project Finish Dates, or withheld while a Validation Warning exists. Never saved, always recalculated.                                                                                                                                               | `forecast`, `Forecast` (`"forecast"` / `"withheld"`)                                                                                                                                                                         | estimate, prediction, schedule                               |
| Base date                                  | The day remaining work starts on: the START date, or today if it is unset or past (also when every Task that follows START is Done), moved off a weekend in weekdays mode. Once every Task is Done, the latest completion date, as it is.                 | `baseDate`, `baseDateReason`, `forecastBaseDate`                                                                                                                                                                             | START date (they differ), project start                      |
| Today                                      | The date no remaining work may start before. Always passed in, never read inside domain logic.                                                                                                                                                            | `today` argument, `todayIsoDate`                                                                                                                                                                                             | now, current time                                            |
| Remaining work                             | The not-Done Tasks. Every forecast quantity counts only these.                                                                                                                                                                                            | (comments, `totalWorkTime`)                                                                                                                                                                                                  | open Tasks, backlog, todo list                               |
| Critical path                              | The longest chain(s) of dependent remaining work: the Tasks with zero slack and the links on a longest chain between them.                                                                                                                                | `remainingWork`, `criticalTaskIds`, `criticalLinks`                                                                                                                                                                          | bottleneck, longest chain (as an identifier)                 |
| Critical-path time / total-work time       | The length of the critical path, and the sum of remaining Durations.                                                                                                                                                                                      | `criticalPathTime`, `totalWorkTime` (`RemainingWorkTime`)                                                                                                                                                                    | effort, total effort, project length                         |
| Maximum parallelism                        | How many Tasks may run at once: unlimited, or 1 (the only MVP setting).                                                                                                                                                                                   | Implicit in `forecast`                                                                                                                                                                                                       | resources, capacity, team size                               |
| Project file                               | The exported plain-text JSON, version `"0.1"`. It round-trips the project exactly.                                                                                                                                                                        | `serializeProject`, `parseProjectFile`, `PROJECT_FILE_VERSION`                                                                                                                                                               | save file, backup, document                                  |
| Export / Import                            | Write the project file / read it back, rejecting a file with a Validation Error.                                                                                                                                                                          | `handleExport`, `parseProjectFile`, `replaceProject`                                                                                                                                                                         | save / load, upload / download (in copy)                     |
| Unexported changes                         | The project's file text differs from the last one exported, imported or started new. Confirmed before New project, Import or Go back replaces the project.                                                                                                | `hasUnexportedChanges`, `markExported`, `ConfirmDialog`                                                                                                                                                                      | unsaved changes, dirty state                                 |
| Diagram                                    | The auto-arranged view of Tasks and dependencies. No layout is stored.                                                                                                                                                                                    | `projectDiagram`, `layoutDiagram`, `Diagram`, `LaidOutDiagram`                                                                                                                                                               | graph view, canvas, Gantt, timeline                          |
| Selection                                  | What the side panel edits: a Task, START, or nothing.                                                                                                                                                                                                     | `Selection`                                                                                                                                                                                                                  | focus, active Task                                           |
| Previous project                           | The project the last accepted edit or replacement superseded. Offered by Go back after a crash.                                                                                                                                                           | `previousProject`, `restorePreviousProject`                                                                                                                                                                                  | undo, history, backup                                        |
| Replacement                                | The whole project swapped at once (New project, Import or Go back).                                                                                                                                                                                       | `replaceProject`, `replacements`                                                                                                                                                                                             | reload, reset                                                |
