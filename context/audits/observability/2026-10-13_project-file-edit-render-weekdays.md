# Observability audit — project file round-trip, edit → render, weekdays day counting (2026-10-13)

## 1. TL;DR

- **Any render-time throw blanks the page and destroys the only copy of the project.** `Planner` owns the project state (`useProject`) and also runs throwing domain code in its own render. There is no error boundary, and `@astrojs/react` mounts with a bare `createRoot`. The user gets a white page, the developer gets one minified `Uncaught …` line with no component stack, and the unexported project is gone along with the reproduction.
- **This is reachable today through Import.** A 133 KB file holding a straight chain of 1,800 Tasks passes `parseProjectFile` and `forecast()`, then `layoutDiagram` throws `RangeError: Maximum call stack size exceeded` inside dagre during the first render. `replaceProject` has already thrown away the project it replaced. Reproduced on the app's own code in Node; not run in a browser.
- **Failures outside render reach only the console, through library defaults.** These include the `void` async import handler, click-handler throws, Astro's hydration error (the skeleton stays forever) and React Flow's warnings, which are compiled out in production. None of them shows anything on screen.
- **Domain invariants are either fatal or silently tolerated.** The same broken state (a stray predecessor id, a missing Task, NaN days) either crashes the island with a thin message (`"The project contains a cycle."` names no Task) or becomes a confidently wrong Project Finish Date.
- **Outcomes the user can't see either way:** Export never confirms, a Validation Error from a blur commit disappears when the same click selects another node, and "today" goes stale in a tab left open overnight.

## 2. Capture model

This is a single-user, browser-only app: static HTML on Cloudflare Workers static assets, with one React 19 island on `/` (`src/pages/index.astro:15`, `client:only="react"`). There is no server code.

- **Error tracker: none, and there may never be one.** The PRD guardrail "no project data leaves the device" is enforced by `connect-src 'none'` (`astro.config.mjs:43`) and checked in built HTML by `npm run check:csp`. Every fix in this report stays on the device: on-screen signals, `console.error`, and keeping the project recoverable.
- **Responder:** the developer is currently the only user (confirmed by the user). A failure counts as "seen" only if it shows on screen or in that browser's DevTools console. It counts as "diagnosable" only if that signal, plus the project state, lets someone reproduce it.
- **Persistence:** none besides the exported file (FR-015 parked). The project lives only in `useState` in `useProject` (`src/hooks/useProject.ts:46`), called from `Planner` (`src/components/planner/Planner.tsx:38-54`).
- **Mount and boundaries:**
  - `@astrojs/react` 7.0.1 calls `createRoot(element)` with no root options (`node_modules/@astrojs/react/dist/client.js:96`).
  - React 19.3's production `defaultOnUncaughtError` only calls `reportGlobalError(error)` and drops the component stack (`node_modules/react-dom/cjs/react-dom-client.production.js:6182-6184`). The root then unmounts.
  - There is no error boundary, `window.onerror`, `unhandledrejection` listener or `astro:hydration-error` listener anywhere in `src/`.
- **Render-time domain code that throws:**
  - `forecast()` (`Planner.tsx:58`), which throws at `forecast.ts:104` and `task-graph.ts:178`
  - `layoutDiagram` (`Diagram.tsx:37`), which throws at `diagram-layout.ts:155` and inside dagre's recursion
  - `forecastBaseDate` (`StartPanel.tsx:46`, `forecast.ts:47`), which throws at `calendar-date.ts:52/96`
  - `predecessorCandidates` (`TaskPanel.tsx:67`)
- **Edit path:** every edit returns an `EditResult`, and `useProject.apply` commits only `ok` results (`useProject.ts:55-62`). Rejections are shown in panel-local state.
- **Logging:** none. There are 0 `console.*` calls in `src/` outside tests, and 0 uses of `Error` `cause`.
- **Third-party reporting defaults:**
  - Astro island load failure: one `console.error("[astro-island] Error hydrating …")` and a cancelable `astro:hydration-error` event; the UI is not changed (`node_modules/astro/dist/runtime/server/astro-island.js:75-88`).
  - React Flow: `onError` defaults to `createDevWarn`, which logs only when `NODE_ENV === 'development'` (`node_modules/@xyflow/system/dist/esm/index.mjs:600-603`). `Diagram.tsx:97` passes no `onError`.
- **Deploy identity:** none in the page. There is no version, commit or build id in the DOM, a meta tag or the console. Stacks are minified, and `dist/` has no sourcemaps. Preview and production builds are byte-identical; only the hostname differs.

**Assumptions (outside the repo, not findings):**

- Cloudflare injects no script on workers.dev or preview URLs, such as Web Analytics auto-inject or Rocket Loader. An injected script would break the hashed CSP and hang the island (see P1). Unconfirmed.
- The `/_astro/* immutable` cache header in `_headers` is not applied to the 404 served for a missing chunk. Unconfirmed.
- The Workers Builds dashboard shows which commit is deployed. That helps, but the browser can't see it. Unconfirmed.

## 4. Systemic root causes

1. **The project state and the throwing derivations share one component, which has no boundary.**
   - **Mechanism:** `Planner.tsx:38-58` holds `useProject` and calls `forecast()` in the same render; `Diagram.tsx:37`, `StartPanel.tsx:46` and `TaskPanel.tsx:67` run more domain code during render. The mount is a bare `createRoot` (`client.js:96`), so React's production default unmounts the root and drops the component stack (`react-dom-client.production.js:6182`).
   - **Why a boundary alone won't do:** an error boundary inside `Planner` cannot catch `Planner`'s own render throw, and one outside it would hold no project to offer for export. The state has to move above the boundary.
   - **Why it exists:** each throw is a reasonable "can't happen" assertion, and the edit layer does enforce the invariants. Nobody planned for the moment an assertion fires.
   - **Explains:** B1, A1, A2 (hang variant), C1.
2. **Import validation was designed against `forecast()`'s invariants, not against what the first render runs.**
   - **Mechanism:** `importProject` (`project-file.ts:369-379`) checks shape, ids and Validation Errors but puts no bound on Task count or chain depth. The only size guard is 5 MB in bytes (`ProjectControls.tsx:13-14`, `:108-113`).
   - **Ordering:** `replaceProject` commits the candidate (`useProject.ts:99-104`) before the render that lays it out.
   - **The gap:** the S-03 roadmap Risk note named this ("forecast() runs during render … would blank the planner"), but it covered only forecast, not dagre layout.
   - **Explains:** A1, A2.
3. **Failures outside render go to library default console reporters, never to the screen.**
   - **Mechanism:** the async handler is fired with `void` and has no local catch (`ProjectControls.tsx:185`), with a rethrow at `project-file.ts:397-399`. React reports event-handler throws with `reportGlobalError`. Astro's hydration failure only calls `console.error` (`astro-island.js:88`). React Flow's `createDevWarn` is compiled out (`@xyflow/system/dist/esm/index.mjs:600-603`).
   - **Why it exists:** each library's default is sensible for an app that has a tracker. This app has none, so the screen is the only alert channel.
   - **Explains:** A3, A4, P1, B8.
4. **Domain code handles a broken invariant two incompatible ways: fatal with a thin message, or silent and plausible.**
   - **Fatal:** `task-graph.ts:178` throws `"The project contains a cycle."` with no path, even though `findCycle` exists. No error carries a `cause`.
   - **Silent:** stray ids are filtered at `task-graph.ts:159` and `diagram-layout.ts:127`, a missing Task is skipped at `forecast.ts:97`, a missing finish day becomes 0 at `forecast.ts:107`, the cycle check fails open at `task-graph.ts:61`, and NaN becomes "Beyond year 9999" at `calendar-date.ts:72` and `:100`.
   - **Outcome:** the same corruption either kills the session or shows a confidently wrong Project Finish Date, depending on which function sees it first.
   - **Explains:** B2, B3, B4, C2, C3.
5. **Outcome signals live in short-lived component state, or don't exist.**
   - **Mechanism:** panel errors live in `TaskPanel`/`StartPanel` state keyed by selection (`Planner.tsx:157`), so a rejected blur commit vanishes when the same click changes the selection. Export sets no state on success (`ProjectControls.tsx:98-100`). `today` is read only when something re-renders (`Planner.tsx:57`).
   - **Explains:** B5, A4, B6, B7, C4.

## 6. Recommended fix order

1. **Lift the project above an error boundary with an "export what you have" fallback (B1; it also contains A1, C1 and the fatal half of B2, B3 and B4).** This is the widest fix: every render throw becomes a visible, recoverable screen instead of data loss, and the fallback's `console.error` can carry the component stack and the serialized project, which is the reproduction. Constraints:
   - The fallback's Export must use the last _committed_ project (`latest.current`), never a half-applied one.
   - Nothing leaves the device.
   - Write the failing test first: a jsdom `Planner` test that forces a render throw and asserts the fallback and its Export (§6.2 of `context/foundation/test-plan.md`).
2. **Bound Task count and chain depth on import, then lay out the candidate before accepting it (A1, A2).** The fix is a new named rule in `project-file.ts`, with a golden-file row, and the same bound should apply in edits. Size the bound from the 200 ms NFR and dagre's measured depth limit, with a margin for Firefox and Safari stacks.
3. **Catch around the import and export handlers and show the error on screen (A3, A4, A5).** These are small local try/catch blocks with `console.error(…, error)` and an on-screen message. Add the "Exported as … at hh:mm" marker here, because S-08 needs it.
4. **Give the console something to work with: messages that name the entity, `cause`, and a build id (B2, C1, P2).** Name the cycle path at `task-graph.ts:178`, add inputs to the `calendar-date` throws, and inject a build meta.
5. **Pick one invariant policy for render-time code: throw (behind the boundary), never default (B3, B4, C2, C3).** Do this before S-07, which adds Done rules to these same functions.
6. **Surface the hydration failure (P1)** with a small bundled script.
7. **The rest: B5 (persist the rejected draft), B6 (midnight re-render), B7, B8, C4, C5, A6, A7, P3.**
